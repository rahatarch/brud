# BrudOS 0.0.2

## Summary
This release closes the kernel gaps found while building real participants on 0.0.1, and adds what a product needs to let its users change what it runs. A host can now reload a running kernel, a participant added by an end user can never stop the kernel from starting, and a composition's official participants can be sealed once per build. Interceptors can also append to a giver's result. It contains breaking changes to kinds, boot options, capabilities and interception: read **Breaking changes** before upgrading.

## Breaking changes
- **kernel:** A kind must list every operation it serves, each with a permission of its own or the kind's default, or the boot is refused. Add `operations` and a permission to each `manifest.kinds` entry. A kind whose operation names only exist at runtime declares `operations: 'open'` with a kind-level permission. ([`cbfbdbb`](https://github.com/rahatarch/brud/commit/cbfbdbbac5a3161c71359d4a2d605e728c4948cc))
- **kernel:** A required boot option that the host did not supply, or supplied under the wrong key or in the wrong shape, now refuses the boot for every hardcore and composed participant, with one error naming each missing field, its scope and the participant. Supply the option in the boot options. ([`4bf75e8`](https://github.com/rahatarch/brud/commit/4bf75e8db61f6d2aa234aa2e13c79c033295e7b2))
- **daemon, protocol:** Removed the `pruned` list, because a participant is no longer silently left out for a missing option. Clients that read it must stop. ([`4bf75e8`](https://github.com/rahatarch/brud/commit/4bf75e8db61f6d2aa234aa2e13c79c033295e7b2))
- **kernel:** `caller.capabilities` is now one read-only view in exposures, kind dispatch and interceptors. It is neither a `Set` nor an array: use `has()`, `size` and iteration instead of `includes()`, and do not change it. ([`fbfe766`](https://github.com/rahatarch/brud/commit/fbfe766181644701da7b8d943253495e048fcba2))
- **kernel:** An interceptor that declares no `stages` now takes part in the output stage only. To see, change or block a call's arguments, declare `stages: ['input']`; without it such an interceptor no longer guards anything. ([`4259ba9`](https://github.com/rahatarch/brud/commit/4259ba9f218944b0e406989bf5a5d389ea254a22))
- **kernel:** A participant that is not declared official and cannot be loaded, admitted or started is left out and the kernel boots without it, where it used to refuse the boot. Read `kernel.abandoned` to see who was left out and why. ([`958f71b`](https://github.com/rahatarch/brud/commit/958f71b342d43aa0db41a71195ef829f9c83db29))
- **kernel:** Removed the unused `PluginMetadata` type and the `metadata` field of `OperationHandler`. ([`1892143`](https://github.com/rahatarch/brud/commit/1892143a41f42c8e750ffc1ac5ee2cf3a2951bd9))

## Changes
### Added
- **kernel:** A host can reload a running kernel with `reload({ configPath? })`. The new config is read, checked and composed while the current kernel keeps running; only then is it stopped and the new one booted. A reload can change the loaded participants but never what the build sealed, and a config that tries is refused with `CONFIG_RELOAD_FROZEN`. ([`b22113d`](https://github.com/rahatarch/brud/commit/b22113dd13492143ab54f1d511acebcd2905f2bb))
- **kernel:** Participants not declared official are loaded participants: they run caged and never stop the boot. One that cannot start is left out, with a participant that depends on it, and every one left out is named with its reason in `kernel.abandoned` and in a warning. If none survive, the kernel boots as shipped. ([`958f71b`](https://github.com/rahatarch/brud/commit/958f71b342d43aa0db41a71195ef829f9c83db29))
- **kernel:** A composition's builder can seal its official participants once per build with `createSeal` and pass the seal and its digest to `bootKernel`. The kernel then refuses a seal that does not match its digest (`SEAL_MISMATCH`) or a sealed participant that is missing or changed (`SEAL_VIOLATION`), and leaves out any entry that declares itself official without being sealed (`PARTICIPANT_NOT_SEALED`). ([`db56698`](https://github.com/rahatarch/brud/commit/db56698c886f34030e8094e7989587de81bba2ce))
- **kernel:** Interceptors can append to a giver's result in an output stage. The caller receives the giver's result unchanged, the additions with the interceptor that made each, and any interceptor that was skipped. An interceptor that returns anything but an append, throws, or exceeds its size limit is skipped and the result is still delivered. Givers can lower the size limits with `outputLimits`. ([`17e5f7d`](https://github.com/rahatarch/brud/commit/17e5f7dfe5f2d9e545a3a6acc076bee6159a9236), [`5ff6b89`](https://github.com/rahatarch/brud/commit/5ff6b898f0fbc97bffbd63e32b327113d5d339ac))
- **kernel:** The router refuses an operation a kind did not declare, or a caller its permission does not admit, before the kind's owner is reached (`operation_not_declared`, `permission_denied`). ([`cbfbdbb`](https://github.com/rahatarch/brud/commit/cbfbdbbac5a3161c71359d4a2d605e728c4948cc))
- **kernel, sdk:** `lastRefusal()` says why the latest `resolve` returned `null`, without revealing whether an exposure exists. This also covers resolving before exposures are attached and from a call the host started. ([`349ba2b`](https://github.com/rahatarch/brud/commit/349ba2b7244c8ae8c02dcf88f77411166a55612d))
- **sdk:** `defineParticipant` accepts `events`, `interceptions`, `interceptionPoints` and `kinds`. ([`ddb084f`](https://github.com/rahatarch/brud/commit/ddb084f3078b5445fb4a28d7437d3cd18d674bf2))
- **docs:** A guide to giving a caged participant recurring work, and a description of the three layers of a composition (hardcore, composed, loaded) in the architecture rules and the config guide. ([`9f462dd`](https://github.com/rahatarch/brud/commit/9f462dd6d9b407b61ee20b727eaa1814193f3d6d), [`9ff8ae6`](https://github.com/rahatarch/brud/commit/9ff8ae6e6943a1e7b513f3f64d66ff6b69e08e99), [`383e839`](https://github.com/rahatarch/brud/commit/383e8396f1efa0dd050d7b97f5cbbd4a64dad35d))

### Changed
- **kernel:** A caged guest stopped at a limit now reports a short message and a stable `reason` (`CAGE_FUEL_LIMIT` or `CAGE_MEMORY_LIMIT`), with the engine's full text in `detail` instead of a backtrace in the message. ([`c8d8f08`](https://github.com/rahatarch/brud/commit/c8d8f08b11476c01ac6ec3fbb4ae3ee2e2314da9), [`3e3455c`](https://github.com/rahatarch/brud/commit/3e3455ce9c2e4dbdd2657ede3dfd9e363bfb149c), [`28f6d54`](https://github.com/rahatarch/brud/commit/28f6d5449231213981ee8710edcdd19c69ce4398))

### Fixed
- **kernel:** Interception's `admit` now says it takes token id strings, names the id to use when a token object is passed, and the guides show it. ([`217f1a5`](https://github.com/rahatarch/brud/commit/217f1a5c41a4760b0474e8c26074f206d58fd114))

### Security
- **kernel:** A participant could add capabilities to the caller record it was shown, so that caller's next call to a capability-gated exposure succeeded. The capabilities view can no longer be changed. No advisory has been issued. ([`fbfe766`](https://github.com/rahatarch/brud/commit/fbfe766181644701da7b8d943253495e048fcba2))

## Known issues
- If a boot fails for a reason that cannot be traced to one loaded participant, every loaded participant is left out once, including good ones. Read `kernel.abandoned` and the warning, fix the cause and reload.
- If a reload fails because of the build itself after the old kernel has stopped, `reload` throws `KERNEL_RELOAD_FAILED` and the host has no running kernel; the old composition is not restarted.
- Without a seal, the config's own `official` flags stand. Pass a seal in a production build.
- Handles that participants resolved before a reload stop working after it, and shutdown does not wait for calls in flight.
